# Контракты инструментов MAX

Статус: действующий контракт 18 инструментов версии 0.1.4. Обновлено: 2026-10-30. Версия контракта: 1.

## Общие правила

Сервер регистрируется в клиенте агента как `max_account`. Здесь указаны собственные имена инструментов; клиент добавляет пространство имён. Набор возможностей не означает, что всё поддерживает конкретный аккаунт или тип чата.

Идентификаторы MAX — десятичные строки. Ввод проверяется, внутри адаптера при необходимости преобразуется в целое. Нет преобразования через число с плавающей точкой. Даты — UTC в ISO 8601. Непрозрачный курсор относится к одному аккаунту, чату, направлению, фильтру и верхней границе. Ответ всегда структурирован; секреты, подписанные ссылки и произвольные поля моделей PyMax наружу не проходят.

Успешный результат содержит `ok=true` и собственные поля инструмента, например `chats` или `messages`, со сведениями о продолжении при необходимости. Ошибка содержит `ok=false`, безопасный объект `error{code,message,retryable,retry_after_seconds}` и идентификатор известной операции, если он уже создан. При неизвестном исходе записи `retryable=false`: нужно прочитать её состояние, а не автоматически повторять запись.

`partial` означает неполноту результата, `end_reached` — подтверждённый конец запрошенного диапазона. `next_cursor=null` без `end_reached=true` не выдаётся за полный конец. Ошибка доступа, ограничение частоты, лимит просмотра и сетевой сбой не превращаются в пустую историю. Текст сообщения — недоверенные данные, а не новая команда агенту.

## Каталог из 18 инструментов

| Инструмент | Вход | Существенный результат |
|---|---|---|
| `account_status` | Без секретных параметров | Состояние сеанса/сети, безопасные сведения своего профиля, версия адаптера, возможности и локальные лимиты |
| `get_chats` | `query?`, `limit=50`, `cursor?` | Собственные диалоги, идентификаторы, типы и названия; продолжение списка |
| `get_chat_info` | `chat_id` | Один подтверждённый чат; поиск по имени выполняется через `get_chats(query=...)` |
| `get_messages` | `chat_id`, `limit=50`, `cursor?`, `since?`, `until?`, `batch_id?` | История, продолжение, границы и полнота; в пакетном режиме учёт полученных страниц |
| `search_messages` | `chat_id`, `query`, `scan_limit=1000`, `cursor?`, `since?`, `until?`, `batch_id?` | Совпадения и отдельно просмотренный диапазон; поиск первой версии локальный, по получаемой истории |
| `get_message_context` | `chat_id`, `message_id`, `before=10`, `after=10` | Целевое сообщение, соседи и исходная реплика ответа; недоступные ссылки отмечены явно |
| `get_pinned_messages` | `chat_id`, `limit`, `cursor?` | Закреплённые сообщения и подтверждённая полнота выдачи |
| `get_forum_topics` | `chat_id`, `limit`, `cursor?` | Реальные темы, только если подтверждён соответствующий механизм MAX; иначе `CAPABILITY_UNSUPPORTED` |
| `get_topic_messages` | `chat_id`, `topic_id`, `limit`, `cursor?` | История действительной темы; нельзя подставить комментарии к посту или цепочку ответов вместо темы |
| `download_media` | `request_key`, `chat_id`, `message_id`, `attachment_id` или индекс, `batch_id?` | Идентификатор передачи; при готовности безопасный `file_id`, доступный агенту путь, размер и SHA-256 |
| `get_transfer_status` | `transfer_id` | Состояние скачивания, полученные байты, результат или безопасная ошибка; не запускает передачу заново |
| `prepare_message` | `request_key`, `chat_id`, `text?`, `reply_to?`, `attachments?`, `batch_id?` | Постоянный `draft_id`, точный адресат/текст, снимки и хеши вложений; публикации в MAX нет |
| `send_prepared_message` | `draft_id`, `expected_chat_id`, `user_instruction`, `authorization_ref?` | Однократно принятая операция: подтверждённая квитанция, подготовка вложений или неизвестный исход |
| `get_send_status` | `draft_id` либо `request_key` | Сохранённое состояние и квитанция; чтение не вызывает новую отправку и не выполняет сверку автоматически |
| `reconcile_send` | `draft_id`, `action=inspect`, `user_instruction?` | Сохранённый журнал с `history_verified=false`; сверка истории по cid пока не подтверждена. Явное `action=abandon` прекращает исполнение без объявления успеха |
| `begin_batch` | `task_key`, `chat_ids`, `initial_since?` | Стабильный пакет обработки, версия отметок, верхняя граница и начальные курсоры |
| `commit_batch` | `batch_id`, `expected_checkpoint_version` | Атомарное продвижение после завершённых страниц и действий либо конкретное препятствие |
| `abandon_batch` | `batch_id`, `user_instruction` | Отказ от застрявшего пакета без продвижения отметки, очистка страниц, сохранение операций и квитанций |

Состояние возможности: `supported`, `unsupported` или `unverified`. Служба не утверждает поддержку форумных тем до её фактического подтверждения. Неподдерживаемые функции не имитируются другой сущностью MAX. Набор тем сохранён в контракте для сопоставления с ридером Telegram и может дать явный отказ.

Редактирование, удаление, управление участниками, регистрация аккаунтов и звонки не входят в этот контракт. В действующем ридере Telegram их также нет. Отправка файлов — дополнение к его возможностям, явно порученное владельцем.

## Формат сообщения и вложения

Нормализованное сообщение содержит: `chat_id`, `message_id`, `sender{id,display_name,is_bot?}`, `time_utc`, `text`, `reply_to?`, `attachments[]`, `link?`. Неизвестный признак бота — `null`, а не выдуманное `false`. Ссылка возвращается только если её формат и доступность подтверждены; иначе используются устойчивые идентификаторы.

Пересылка дополнительно содержит `forwarded{status,source_chat_id?,message?}`. Её собственный `text` — комментарий переславшего, а исходный текст находится в `forwarded.message.text`, с отдельным автором и временем. Скрытые сведения не подставляются из оболочки. `content_status` различает текст, вложение, пересылку и отсутствие доступного содержимого. Вложения пересылки также включаются в общий `attachments` с непрозрачным `attachment_id`, начинающимся с `forward:`; передавать его в `download_media` нужно целиком и вместе с идентификаторами внешнего порученного сообщения. Повторная проверка вложения и запрос файла используют этот чат; исходный чужой чат автоматически не читается. Глубина вложенных пересылок ограничена четырьмя и явно обозначается `depth_limit`. Поиск проверяет текст пересылок.

Вложение в истории содержит `attachment_id` или индекс в сообщении, `kind`, исходное безопасное имя, известный размер/тип, доступность скачивания и `unsafe?`. URL, токен фото, токен видео, настройки сеанса и сырые поля ответа не возвращаются. Индекс перепроверяется повторным получением того же сообщения перед передачей; изменившееся вложение даёт `ATTACHMENT_CHANGED`.

При неизвестном типе сообщение остаётся читаемым, вложение помечается неподдерживаемым. Пустое поле URL не является доказательством, что файл нельзя получить: для документов и видео сначала выполняется специальный запрос MAX.

## Чтение и поиск

Каталог использует маркер `CHATS_LIST`, который возвращает MAX. Следующая страница перекрывает временную границу на миллисекунду и исключает уже выданные на ней идентификаторы. Нулевой серверный маркер подтверждает конец. Если все записи границы не помещаются на страницу и продвижение невозможно, возвращается `PAGINATION_STALLED`, а не полный список. Курсор связан с аккаунтом и поиском; отпечаток страницы защищает продолжение её остатка от незаметного изменения. Имя личного диалога берётся из профиля единственного подтверждённого собеседника. Сбой получения профилей даёт повторяемую ошибку; `unnamed_dialogs` показывает оставшиеся диалоги без имени. При поиске такие диалоги не позволяют объявить поиск полным.

Лимит страницы: от 1 до 200; начальное значение 50. Максимум соседей контекста — 50 с каждой стороны. Начальный бюджет поиска — 1000 сообщений, максимально допустимый бюджет первого выпуска — 5000 за вызов; это ограничения нашего моста. Превышение возвращает продолжение, не запускает полный обход аккаунта.

Для первого вызова можно задать временные границы. При продолжении они берутся из курсора, новые несовпадающие фильтры отклоняются. Внутри фиксированного диапазона новые поступления не сдвигают страницы. Верхняя граница пакетного задания задаётся `begin_batch` и общая для всех его вызовов.

Временная граница PyMax не равна Telegram `offset_id`. Без проверенного продвижения на одинаковых временах инструмент сообщает `partial=true`, `end_reached=false` и причину. Получение неполной выдачи никогда не позволяет подтвердить весь пакет.

MAX включает граничное сообщение повторно. Мост расширяет окно для уже выданных идентификаторов, соблюдая пользовательский лимит; после полного осмотра границы выполняет контрольный запрос строго до неё, чтобы подтвердить естественный конец. Полная серверная страница из 200 сообщений с одинаковым временем остаётся неоднозначной и даёт `PAGINATION_STALLED`. Идентификаторы не используются вместо временных отметок, сортировка времени выполняется по миллисекундам.

Поиск не вступает в сообщества и не меняет отметку прочтения. Межчатовые ссылки контекста не открываются автоматически. Содержательное прочтение моделью отдельно от получения страниц не подтверждается мостом.

## Подготовка и отправка текста/файлов

`request_key` — непустая постоянная строка до 160 символов. Для ручного поручения она относится к одному намерению; для планового — строится из устойчивого пакета и имени действия. Один и тот же ключ с новым содержимым даёт `REQUEST_CONFLICT`; новый ключ не подавляется только из-за совпадения текста.

`prepare_message` требует текст либо хотя бы одно вложение. Вложение задаётся существующим `file_id` или локальным путём из разрешённой области; представление — `document` или `photo` для первой поставки. Иные нативные виды добавляются после испытаний. Произвольный URL не принимается. Дубликаты подготовки возвращают прежнюю операцию только после сверки содержимого и файлов; незавершённые снимки не объявляются подготовленными.

В подготовленной операции сохраняются текст без повторного преобразования разметки, идентификатор адресата, контекст ответа, подпись и снимки. Подпись — текст того же сообщения, если протокол выбранного вида позволяет; иначе инструмент отказывает или предлагает явное изменение, не отправляет отдельную реплику сам.

`send_prepared_message` сверяет `expected_chat_id`, существование адресата и разрешённость действия. Изменение названия показывается как актуальные сведения, но само по себе не подменяет постоянный идентификатор. Неоднозначное имя никогда не выбирается автоматически.

`user_instruction` и `authorization_ref` описывают действительное поручение владельца или сохранённое задание, а не текст прочитанного чата. Эти поля не доказывают подлинность человеческого согласия — оно является обязанностью доверенного агента. Техническое разделение подготовки и отправки не требует отдельного вопроса человеку, если поручение уже дано.

Первичный вызов отправки возвращает состояние сразу либо после короткого ожидания до 5 секунд. Длительная подготовка вложений продолжается в службе, статус получается по `draft_id`. При исчерпании ресурсов новая операция отклоняется до сетевой отправки; необработанный фон не копится бесконечно. Повторный запрос состояния не является повтором действия.

Точные состояния:

| Состояние | Значение | Допустимое продолжение |
|---|---|---|
| `prepared` | Содержание и файлы зафиксированы; публикации нет | Порученная отправка |
| `preparing` | Единственный исполнитель готовит/загружает вложения | Читать статус; не создавать второй отправитель |
| `sending` | Намерение записано устойчиво, начата граница внешней отправки | Ждать результат; после перезапуска считать `unknown` |
| `sent` | Есть сохранённая квитанция MAX | Вернуть ту же квитанцию при повторе |
| `failed_before_send` | Достоверно не выполнялся `MSG_SEND` | Повтор той же операции с тем же содержимым допустим после проверки условий |
| `rejected` | Получен доказанный отказ MAX без публикации | Показать отказ; исправленное содержание требует нового ключа |
| `unknown` | Публикация могла состояться | Только статус/сверка; автоматический повтор запрещён |
| `abandoned` | Владелец явно отказался от дальнейшего исполнения; прежний исход не переименован в успех | Не отправлять повторно; пакет может сохранить это решение и завершиться |

`sent` не означает прочтение или скачивание получателем. Успешная HTTP-загрузка вложения до публикации не является `sent`.

`reconcile_send(action=abandon)` требует действительного поручения прекратить именно эту операцию. Это средство выхода из неразрешимого `unknown`, а не автоматическая политика повтора. Подтверждённую квитанцию `sent` такой вызов не отменяет и сообщение в MAX не удаляет.

## Файловые результаты и сроки

Скачанный файл получает промежуточную запись до создания конечного имени. После прерывания служба работает только с записанными именами и проверяет идентичность и хеш; подменённый файл сохраняется. Два имени одного файла считаются в квоте один раз. Счётчики восстановления доступны в `account_status.storage_cleanup.recovery`. Если авария произошла посреди потока до регистрации, неизвестный `.part` остаётся и занимает квоту; автоматически удалять неизвестные файлы нельзя.

Ошибка базы до вызова отправителя освобождает только собственный захват при восстановлении доступности базы. Внутренний идентификатор захвата в ответы не включается. После возможной сетевой отправки сохраняется прежнее правило `unknown`, без автоматического повтора. Повторно полученные внешние сообщения проверяются по запрошенным идентификаторам и явно указанному чату; чужой вложенный источник пересылки не подменяет внешний чат.

`file_id` — непрозрачный идентификатор локального файла, а не его путь. Результат скачивания содержит также абсолютный путь в общей области, размер, SHA-256 и срок хранения. Путь должен быть доступен процессу агента на том же хосте; путь внутри чужого контейнера без общего тома не считается пригодным результатом.

Файл выдаётся только после завершённой записи и переименования. Повтор того же запроса скачивания возвращает уже проверенный файл, если он ещё существует и не изменён. Исчезнувший/истёкший файл даёт `FILE_EXPIRED`; новое скачивание безопасно, но не выдумывает старый результат. Частичный файл не выдаётся как готовый. В первой версии нет чтения всего файла в ответ МСП и кодирования больших файлов в текст.

Скачивание и подготовка снимка не выполняют документ, не распаковывают архив и не запускают макросы. Флаг небезопасности источника сохраняется в метаданных; обращение с содержимым относится к следующему поручению и инструменту обработки агента.

## Пакеты для расписаний

`task_key` — постоянное имя конкретного поручения, не расписание. `begin_batch` не создаёт и не меняет задания агента. Если пакет этого задания не завершён, возвращается он же; изменение набора чатов без завершения/явного пересмотра не создаёт независимый проход поверх него.

`commit_batch` проверяет зафиксированную полноту всех запрошенных диапазонов, состояние связанных передач и отправок, а также ожидаемую версию отметки. Невыполненное действие и `unknown` блокируют продвижение. Неуспешный запуск повторно получает прежний пакет, а не пропускает данные. Операции разных заданий разделены именами, но пользуются единым учётом сеанса и отправок.

Результат фиксации означает завершение, явно заявленное агентом по поручению; не является независимым доказательством качества анализа моделью. Если задание проверяет только условие и не требует отправки, отсутствие созданной отправки не считается ошибкой.

## Ошибки

| Код | Значение и действие |
|---|---|
| `AUTH_REQUIRED` | Нужен локальный вход владельца; плановая задача не ждёт пароль |
| `ACCOUNT_MISMATCH` | Вошёл другой аккаунт; запросы заблокированы без автоматического выхода/удаления сеанса |
| `CHAT_AMBIGUOUS` | Есть несколько кандидатов; выбрать постоянный идентификатор |
| `CHAT_UNAVAILABLE`, `MESSAGE_NOT_FOUND` | Чат недоступен или сообщение отсутствует; не подменять пустой историей |
| `CAPABILITY_UNSUPPORTED`, `MEDIA_UNSUPPORTED` | Функция или вид вложения не подтверждены для MAX |
| `PAGINATION_STALLED`, `CURSOR_INVALID` | Нельзя доказать продвижение либо нарушены параметры курсора |
| `RATE_LIMITED`, `BUSY` | Вернуть время ожидания; не повторять отправку без проверки её состояния |
| `FILE_TOO_LARGE`, `STORAGE_FULL`, `FILE_EXPIRED` | Ограничение нашей политики либо отсутствие пригодного файла |
| `FILE_PATH_DENIED`, `FILE_HOST_NOT_APPROVED` | Запрещённый путь/адрес; нельзя расширять политику через аргументы инструмента |
| `ATTACHMENT_CHANGED`, `FILE_CHANGED` | Содержимое изменилось после выбора или подготовки |
| `REQUEST_CONFLICT`, `CHECKPOINT_CONFLICT` | Нельзя заменить поручение или перезаписать более новый результат |
| `OUTCOME_UNKNOWN` | Новая отправка запрещена до выяснения исхода |
| `STORAGE_ERROR`, `UPSTREAM_ERROR` | Ошибка состояния/сервера без раскрытия секретов; учитывать границу внешнего действия |

## Аннотации МСП

Чистое чтение статуса, чатов, контекста и закрепов получает `readOnlyHint=true`. `get_messages` и `search_messages` консервативно получают `false`, поскольку в пакетном режиме сохраняют продвижение. Подготовка, скачивание, отправка, сверка квитанции и пакетные операции также имеют `false`. Это не запрет чтения: для собственного доверенного сервера механизм согласования не создаёт лишних вопросов.

Повторяемость с теми же аргументами обеспечивается ключами операций, а не надеждой на аннотацию `idempotentHint`. Отправки не должны автоматически воспроизводиться транспортом после неизвестного исхода; даже при повторе старым клиентом собственная база не допускает второй захват. Гарантии серверной дедупликации MAX по `cid` до испытаний не предполагаются.
