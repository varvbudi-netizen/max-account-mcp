# Разработка и проверки

Статус: воспроизводимые команды версии 0.1.4. Обновлено: 2026-10-30.

Рабочий каталог всех команд — корень клона. Нужны Python 3.11+ и отдельное окружение. На Linux после его активации:

```sh
python -m pip install -r requirements.lock . pytest==9.2.0
python -m pip check
python scripts/check_project.py
python scripts/check_project.py --ready
python -m pytest -p no:cacheprovider -q
python -m pip wheel --no-deps . --wheel-dir dist
```

Проверки документов подтверждают структуру и ссылки. Набор pytest использует искусственные сообщения, временные базы и локальные HTTP-серверы: он не требует авторизации MAX. Проверки защищённого открытия, удаления и прав требуют Linux/POSIX. Windows пропускает неподдерживаемые случаи и не заменяет проверку целевой Linux-среды.

| Изменение | Основная область проверки |
|---|---|
| Владелец, идентичность, страницы, пересылки | `test_account`, `test_message_identity`, `test_history_pagination`, `test_forwarded_messages`, `test_messages` |
| Пакеты, квитанции, повтор и миграция | `test_state`, `test_outbox`, `test_outbox_recovery` |
| Файлы, гонки, восстановление и очистка | `test_media`, `test_media_recovery`, `test_cleanup_permissions` |
| Доступ и локальный протокол | `test_app`, `test_health_security`, `test_config` |

В наборе есть дополнительные параметризованные случаи; число случаев зависит от способа их учёта и платформы. Успех тестов не доказывает поддержку всех функций MAX. Реальную отправку проверяйте только по поручению владельца и на согласованном адресате.

`python scripts/audit-dependencies.py` обращается к OSV и передаёт только публичные имена пакетов и версии. Это проверка известных записей базы на момент запроса, а не полный аудит зависимостей. Её доступность зависит от сети.

Для следующего изменения создайте [карточку](tasks/TEMPLATE.md), обновите контракт и затронутые документы. В историю не включаются настройки экземпляра, рабочие данные, окружения, сборки и локальные карты кода. Контроль состава публичной поставки проводится по фактически добавленным файлам и объектам Git, а не только по `.gitignore`.
