# Установка и эксплуатация

Статус: переносимая инструкция Linux для 0.1.4. Обновлено: 2026-10-30.

## Локальный запуск

Используйте [команды README](../README.md#быстрый-запуск-на-linux). Все относительные пути вычисляются от файла TOML, а не текущей папки запуска. Не используйте один сеанс в двух процессах. Нужен Python 3.11+ и доступ к закреплённым зависимостям. Служба по умолчанию не разрешает ни одного файлового домена.

`init` создаёт закрытые каталоги и случайный ключ МСП; существующий ключ не заменяется. `login` требует интерактивного терминала владельца. Войдите до запуска `serve`; при повторном входе сначала остановите службу. Не сохраняйте подтверждение входа и авторизацию в репозитории.

`NO_PROXY` и другие переменные не управляют системным VPN: обеспечьте маршрут к MAX на уровне хоста. Не отключайте проверку TLS. Диагностика без аккаунта: `python scripts/probe-max-network.py`.

## Отдельная служба systemd

Ниже принята стандартная схема, не адреса какой-либо существующей установки:

- приложение и окружение: `/opt/max-account`;
- конфигурация: `/etc/max-account/config.toml`, ключ: `/etc/max-account/mcp.key`;
- закрытое состояние: `/var/lib/max-account`, владелец `max-account`, права `0700`;
- обмен: `/srv/max-account/exchange/inbox` и `outbox`, отдельная группа только для нужного клиента;
- образец службы: [max-account.service](../scripts/max-account.service).

Администратор создаёт системного пользователя без обычного входа, размещает чистый клон в `/opt/max-account`, создаёт там `.venv` и устанавливает `requirements.lock` и пакет. В TOML задаются абсолютные пути: `session_dir=/var/lib/max-account/session`, `storage_dir=/var/lib/max-account/spool`, `state_db=/var/lib/max-account/state.db` и указанные выше пути ключа и обмена. Строковые значения TOML заключаются в кавычки.

Родитель ключа должен допускать создание ключа службой при `init` и не быть доступен для чужой записи. Сам ключ принадлежит службе, права `0600`. Конфигурация меняется администратором. Папка скачивания принадлежит службе; общий родитель защищён sticky bit, запрещающим другому участнику группы подменять принадлежащие службе файлы. Доступ агента к обмену настраивается через отдельную группу без доступа к закрытому состоянию.

После подготовки каталогов и настроек:

```sh
sudo -u max-account /opt/max-account/.venv/bin/max-account --config /etc/max-account/config.toml init
sudo -u max-account /opt/max-account/.venv/bin/max-account --config /etc/max-account/config.toml login
sudo install -m 0644 scripts/max-account.service /etc/systemd/system/max-account.service
sudo systemctl daemon-reload
sudo systemctl enable --now max-account.service
sudo systemctl is-active max-account.service
```

Проверьте пути и доступность ключа до запуска. Вызов `scripts/smoke-service.py` предназначен для этой стандартной схемы и запускается от пользователя службы. Проверка подтверждает защищённый транспорт, набор инструментов и состояние; настоящую отправку не выполняет.

## Файловые домены

Разрешаются только точные имена, полученные из проверенного ответа MAX. Для документов и фото наблюдались `fd.oneme.ru` и `i.oneme.ru`, но это не основание автоматически разрешать любые соседние домены, загрузки или перенаправления. Новый адрес проверяет владелец. Ошибку `FILE_HOST_NOT_APPROVED` нельзя обходить передачей произвольного URL через инструмент. Изменение конфигурации применяется перезапуском.

## Обновление и восстановление

Остановите службу. Сохраните закрытую резервную копию всего состояния и конфигурации с исходными правами; для SQLite используйте остановленную базу либо штатное согласованное резервирование. Архив с сеансом является секретом. Сначала проверяйте новую версию в отдельной среде на копии тестовых данных. Не запускайте два владельца одного сеанса и не переносите рабочую авторизацию в проверки.

После установки проверьте версию `account_status`, состояние владельца и порученный сценарий. Откат кода без соответствующей копии базы может быть несовместим с миграцией. Отметки и журнал отправок нельзя удалять для повторной попытки: неизвестный исход может привести к дублю. Готовность службы не доказывает доставку предыдущего сообщения.

Промежуточные файлы, неизвестные базе после аварии до регистрации, проверяются вручную при остановленной службе. Не удаляйте всю область обмена или состояние ради освобождения места. Известные ограничения — [STATUS.md](STATUS.md).
